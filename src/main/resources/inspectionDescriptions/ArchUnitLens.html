Reports violations for the conservative ArchUnit rule subset that ArchUnit Lens can statically interpret. ArchUnit tests remain the final authority; this inspection is early editor feedback only.

The canonical support contract lives in docs/rule-support-matrix.md. Current live-warning families include package dependency bans for explicit imports and resolved Java references, class suffix rules, forbidden annotations, annotation exclusivity, typed class conventions over annotation/meta-annotation/package/suffix/interface/enum/record/final-modifier facts, QueryMapper-style interface rules, literal class/method meta-annotation rules, and positive method/constructor declaration conventions for private constructors, static methods, and resolved exact raw return types, plus statically decidable negative noFields()/noMethods() annotation, name, modifier, and declaring-class rules. Negative polarity is applied once to the complete supported condition tree. Exact noClasses() field accesses and zero-argument method calls are also supported, including bounded orShould() when every sibling is exact and statically resolved. Class predicate and()/or() and condition andShould() are live only when every leaf is statically supported.

Unsupported, custom, or ambiguous helper-based rules are retained as Rule Overview metadata when possible but do not produce warnings. Unsupported field/method/constructor declarations, parameterized method/constructor access, access predicates, method references, and unsupported siblings remain metadata-only. Open the ArchUnit Lens tool window to review supported and unsupported discovered rules, scopes, reasons, unsupported reasons, and scan metrics.
