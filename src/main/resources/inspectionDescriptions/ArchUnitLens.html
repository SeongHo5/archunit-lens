Reports violations for the conservative ArchUnit rule subset that ArchUnit Lens can statically interpret. ArchUnit tests remain the final authority; this inspection is early editor feedback only. Live rules require a uniquely resolved static entry-point declaration owned by com.tngtech.archunit.lang.syntax.ArchRuleDefinition. Qualified calls and explicit or wildcard static imports are supported when their owner resolves. Same-name project helpers and unresolved or ambiguous roots remain metadata-only; helper bodies are never interpreted.

The canonical support contract lives in docs/rule-support-matrix.md. Current live-warning families include package dependency bans for explicit imports and resolved Java references, class suffix rules, forbidden annotations, annotation exclusivity, typed class conventions over annotation/meta-annotation/package/suffix/interface/enum/record/final-modifier facts, QueryMapper-style interface rules, literal class/method meta-annotation rules, and positive method/constructor declaration conventions for private constructors, static methods, and resolved exact raw return types, plus statically decidable negative noFields()/noMethods() annotation, name, modifier, and declaring-class rules. Negative polarity is applied once to the complete supported condition tree. Exact noClasses() field accesses, signature-aware method calls, and constructor accesses are also supported. Inlined primitive/String constant reads are excluded; nonconstant reads and explicit writes remain detectable. Declaration initializer writes are not synthesized from PSI. Source non-static member constructors include the immediately enclosing class type as the first JVM parameter. Compiled inner constructor signatures that cannot be proven produce no warning. Class predicate and()/or(), condition andShould(), and left-associative code-access andShould()/orShould() are live only when every leaf is exact, statically supported, and resolved.

Package scope combines literal/Java constant @AnalyzeClasses(packages = ...) and resolved packagesOf class literals. A bare annotation or empty arrays use the annotated class package. Unresolved scope entries, nonempty location providers/import options/individual classes, and whole-classpath imports keep the whole rule metadata-only; project providers and options are never executed.

Unsupported, custom, or ambiguous helper-based rules are retained as Rule Overview metadata when possible but do not produce warnings. Unsupported field/method/constructor declarations, non-literal method/constructor access schemas, access predicates, method references, and unsupported siblings remain metadata-only.
